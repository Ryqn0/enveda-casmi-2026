# Code guide — every module, function by function, line by line

This guide walks through the code in `src/casmi/` in the **order it was
written**, one file per module, then the scripts that use it. It is meant to be
read in order: each part assumes the ones before it, and Python concepts are
explained the first time they appear.

The walkthrough (`docs/14-walkthrough.md`) tells the *story*; this guide
explains the *code*.

## How the modules depend on each other

An arrow means "imports from". Nothing imports `rank.py` except the notebook
and one validation script — it is the top of the pipeline.

```
official_metric.py ──► metric.py
                            │ (inchikey14 used by the scripts)
pool.py ────────────────────┤
analog.py ◄──────── fpnet.py (candidate_bits uses morgan_fp)
library.py                  │
fragment.py                 │
ranker.py                   │
   │                        │
   └───────► rank.py ◄──────┘   (uses pool, analog, library, fpnet, fragment, ranker)
                │
                ▼
      kaggle/submit_notebook.py  (embeds all seven modules, in this order:
                                  pool, analog, library, fpnet, fragment, ranker, rank)
```

## Try it as you read

Every module in `src/casmi/` ends with a `_self_check()` you can run on its own:

```bash
uv run python src/casmi/metric.py       # prints "metric self-check passed ..."
uv run python src/casmi/pool.py
uv run python src/casmi/analog.py
uv run python src/casmi/fpnet.py
uv run python src/casmi/fragment.py
uv run python src/casmi/ranker.py
```

Reading a self-check is often the fastest way to learn what a function
promises: each `assert` is one promise, written as code.
